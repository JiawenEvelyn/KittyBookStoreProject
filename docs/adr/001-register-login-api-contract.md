# ADR-001：register / login 接口契约

| | |
|---|---|
| 日期 | 2026-09-06 |
| 状态 | Accepted |
| 归属里程碑 | M1-2 |
| 相关约束 | CLAUDE.md 第 7 节「面向多端的架构约束」#3、#4 |

---

## 1. 背景

现有 register / login 两个接口有三个必须一起解决的问题：

1. **风格不一致**：`register` 收 JSON body，`login` 把参数拼在 URL 上（`POST /user/login?name=kitty&password=pwd`）
2. **拿不到新用户的 id**：两者都只返回一句中文字符串。而主键是 UUID，客户端猜不出来 —— 这导致 `GET /user/{id}` 事实上**任何客户端都调不到**
3. **路径没有版本前缀**，违反多端架构约束 #3

三个问题都属于「接口契约」，必须一次定完而不是分批改 —— 每改一次契约都是一次破坏性变更。

**为什么是现在做**：目前**没有任何客户端在调这些接口**（M3 才做 Web 前端，App 更晚），改动成本近乎为零。M3 之后成本急剧上升。

---

## 2. 备选方案

### 2.1 `register` 成功返回什么
- **A**：只返回新用户的 id 字符串
- **B**：返回完整 `UserVO`
- **C**：返回 `204 No Content`，让客户端自己再查一次

### 2.2 `login` 的入参形式
- **A**：维持 form 参数（`?name=&password=`）
- **B**：改成 JSON body

### 2.3 `login` 的返回结构（M2 会加 token）
- **A**：直接返回 `Result<UserVO>`，M2 时把 `data` 的类型整个换掉
- **B**：现在就建 `LoginVO { UserVO user; String token; }`，`token` 暂时填 `null`
- **C**：现在只建 `LoginVO { UserVO user; }`，M2 时再加 `token` 字段

### 2.4 `/api/v1` 前缀加在哪
- **A**：写在每个 Controller 的 `@RequestMapping` 上
- **B**：`server.servlet.context-path=/api/v1` 全局配置
- **C**：`WebMvcConfigurer.configurePathMatch` 按包名/注解统一加

---

## 3. 决策

| 项 | 选定 |
|---|---|
| `register` 返回 | **2.1-B** —— 完整 `UserVO`，状态码 `201 Created` |
| `login` 入参 | **2.2-B** —— JSON body，新建 `dto/LoginRequest` |
| `login` 返回 | **2.3-C** —— 新建 `vo/LoginVO { UserVO user; }`，M2 再加 `token` |
| 版本前缀 | **2.4-A** —— 写在每个 Controller 上；`HelloController` **不加** |
| 资源路径 | 用复数：`/api/v1/users/{id}` |

---

## 4. 理由

### 4.1 `register` 返回完整 UserVO（选 B）

注册成功后前端通常直接进入已登录界面，B 省掉一次往返；A 只给 id，前端必须再查一次；C 要往返两次，最差。

状态码用 `201 Created` 而不是 `200`：本项目采用「混合式响应协议」（HTTP 状态码表达**哪一类**问题，body 的 code 表达**具体哪个**问题），既然状态码是有语义的，创建成功就该用 201。REST 惯例还建议附 `Location: /api/v1/users/{id}` 响应头，**本期不做**（见第 6 节）。

### 4.2 `login` 改 JSON body（选 B）—— 这条不是取舍，是安全底线

密码出现在 URL query 里，至少会被五处记录下来：

| 泄露点 | 说明 |
|---|---|
| 服务端 access log | Tomcat / Nginx 默认记录完整 URL |
| 网关 / 反向代理 / CDN | 每一跳各记一份 |
| 浏览器历史记录 | Web 端时密码留在用户自己的机器上 |
| **Referer 头** | 页面上若有外链，浏览器会把当前 URL（含密码）发给第三方 |
| APM / 监控 | 按 URL 聚合统计时把密码当成 URL 的一部分存下来 |

**HTTPS 挡不住这件事** —— 它加密的是传输过程，请求到达服务端后 URL 就是明文，照样进日志。

改成 JSON body 顺带解决了接口风格不一致（问题清单 #4）。

### 4.3 `login` 返回 `LoginVO`，但现在不放 token（选 C）

- 选 A：M2 要把 `data` 的类型整个换掉，是破坏性变更
- 选 B：客户端看到 `"token": null` 容易当成 bug；填假值（`"not-implemented"`）更糟，假数据早晚有人当真
- 选 C：**现在就有了一个专属的类名和一个可以往里加东西的位置**。`token` 到 M2 时只是**新增一个字段** —— 加字段不是破坏性变更，老客户端会忽略不认识的字段

为什么是 `LoginVO { UserVO user; }` 组合，而不是把 user 的字段平铺进去：将来 `UserVO` 加字段时，组合写法自动跟上；平铺写法要在两个地方各改一遍，**而漏改一处是必然会发生的**。

### 4.4 版本前缀写在每个 Controller（选 A）—— 重点是为什么否决 B

先澄清一个容易搞错的前提：

> **`v1` / `v2` 是接口契约的「代际」，不是客户端的「种类」。** Web 和 App 调的是**同一个 v1**，不存在「Web 走 v1、App 走 v2」这回事 —— 那会变成两套要各自维护的接口，业务逻辑重复两遍。

版本号的真正动机是**时间维度**：App 用户不升级，老版本永远在调你的旧接口。所以当契约必须做破坏性变更时，新旧两代得**同时活着** —— 老 App 继续用 v1，新版本用 v2，等老用户升级完再下线 v1。

由此**直接否决 B**：`server.servlet.context-path` 全局只能有一个值。将来改成 `/api/v2`，所有 v1 接口瞬间 404，v1 与 v2 无法并存。**用 B 等于让版本号退化成一个装饰，恰好毁掉它存在的全部意义。** 附带问题：全局前缀会把运维端点也带上前缀（`/api/v1/actuator/health`），而版本号在语义上只属于业务 API。

C 能满足并存要求，但当前只有一个业务 Controller，为此引入一个新扩展点收益不足（见第 5 节第 1 条的重构条件）。

`HelloController` 不加前缀，同理：它是探活 / 调试端点，不是业务 API。

### 4.5 资源路径用复数

REST 惯例：集合资源用复数（`/users/{id}`）。现在改零成本，有客户端之后再改就要动客户端。

---

## 5. 代价与后果

1. **前缀写死在每个 Controller，代价是重复。**
   触发重构的条件：业务 Controller 超过 5 个，**或**第一次要发布 v2 时。届时换成 2.4-C（`WebMvcConfigurer` 按 `controller.v1` / `controller.v2` 包名加前缀），C 同样支持并存，迁移成本可控。

2. **`LoginVO` 现在只包一个 `user` 字段，看起来是一层多余的包装。**
   接受这个"多余"，换来的是 M2 加 token 时改动为零。风险只在"M2 最终不做 JWT"，而那被多端约束 #2 排除了。代价上限是一个类文件。

3. **`register` 返回完整 `UserVO`，把它和 `GET /users/{id}` 的返回结构绑定了。**
   将来 `UserVO` 加字段（比如"已读书目数"），`register` 也会跟着返回一堆零值。**不预先拆分** —— 等这个问题真的出现时，再拆出独立的 `RegisterVO`。

4. **本 ADR 定的契约什么时候冻结？不是现在。**
   多端约束 #4 从**第一个真实客户端上线**那一刻才生效，分两级：
   - **M3 Web 上线后 → 半冻结**：还能改，但必须前后端同步发版
   - **App 上线后 → 完全冻结**

   所以 **M3 之前是重构响应结构的最后窗口期，该改的现在就改。**

5. **什么情况下需要推翻本 ADR。**
   若产品方向改为"只做 Web、永不做 App"，则版本前缀和 `LoginVO` 的预留都失去意义，可以简化。但那要先推翻 CLAUDE.md 第 7 节的多端架构约束 —— 那是更上位的决策，不是本 ADR 能单独改的。

---

## 6. 本期明确不做

| 项 | 归属 |
|---|---|
| `Location` 响应头 | 可选，暂不做 |
| JWT token 签发与校验、刷新令牌 | M2 |
| 密码加密存储（BCrypt） | M2（问题清单 #1） |
| 接口鉴权（当前 `GET /users/{id}` 存在 IDOR 越权） | M2（问题清单 #2） |
